# Планировщик комнаты

Веб-приложение на Django для расстановки мебели в комнате. План рисуется в браузере: мебель можно перетаскивать, поворачивать, менять размеры, копировать и удалять, а расстояния до стен и соседних предметов видны сразу. У каждой комнаты может быть несколько вариантов планировки, их удобно сравнивать по миниатюрам. Все хранится в базе данных, и сервер проверяет, что мебель не выходит за стены комнаты.

Учебный проект: изучаю на нем Django.

## Возможности

- Интерактивный редактор плана (SVG + JavaScript).
- Несколько вариантов планировки одной комнаты: «Сохранить» перезаписывает текущий вариант, «Сохранить как…» создает новый.
- Список вариантов с миниатюрами, нарисованными в шаблоне Django.
- Серверная проверка: размеры больше нуля, мебель не выходит за стены, названия вариантов в комнате не повторяются.
- Сохранение в транзакции: план записывается целиком или не записывается вовсе.
- Защита от CSRF при сохранении.
- Оптимизация запросов к базе: `select_related`, `prefetch_related`, `annotate`.
- Секреты и настройки окружения в файле `.env`.

## Стек

- Python 3, Django
- SQLite
- HTML, CSS, JavaScript без фреймворков
- python-dotenv, django-debug-toolbar (только при разработке)

## Установка и запуск

```bash
git clone https://github.com/gnomazhestvo/home_planner.git
cd home_planner

python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

cd home_planner                 # папка с manage.py
cp .env.example .env
```

В `.env` впишите свой секретный ключ. Сгенерировать его можно так:

```bash
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

Ключ указывается в одинарных кавычках: `SECRET_KEY='...'`.

Дальше:

```bash
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Главная страница: http://127.0.0.1:8000/

### Первые данные

Создавать комнаты со страниц пока нельзя, поэтому первую комнату и первый вариант нужно завести в админке http://127.0.0.1:8000/admin/:

1. «Комнаты» → добавить комнату с размерами в сантиметрах.
2. «Варианты» → добавить вариант для этой комнаты. Мебель можно сразу добавить в нем или потом расставить в редакторе.

Дальше новые варианты удобнее создавать из редактора кнопкой «Сохранить как…».

### Переменные окружения

| Переменная | Что задает | Пример |
|---|---|---|
| `SECRET_KEY` | Секретный ключ Django. Обязательна, без нее проект не запустится | `'...'` |
| `DEBUG` | Режим отладки. Включается только значением `True`, по умолчанию выключен | `True` |

При `DEBUG=True` подключается django-debug-toolbar.

## Как устроено

### Модели

- `Room` — комната: название и размеры по осям x и y в сантиметрах.
- `Layout` — вариант планировки комнаты: название (уникальное в пределах комнаты) и дата создания.
- `Item` — предмет мебели в варианте: тип, название, координаты левого верхнего угла и размеры. Флаг `wall` отмечает предметы, которые висят на стене (например, телевизор): они не конфликтуют с мебелью на полу.

Связи: комната → варианты → мебель. Координаты отсчитываются от левой и верхней стены комнаты.

### Страницы

| Адрес | Что показывает |
|---|---|
| `/` | Список комнат |
| `/rooms/<id>/` | Варианты планировки комнаты с миниатюрами |
| `/layouts/<id>/` | Редактор варианта |
| `/admin/` | Админка Django |

### JSON API

| Адрес | Метод | Что делает |
|---|---|---|
| `/layouts/<id>/plan/` | GET | План варианта |
| `/layouts/<id>/plan/` | POST | Сохранить план варианта целиком |
| `/rooms/<id>/layouts/` | POST | Создать новый вариант в комнате, ответ 201 |

Все POST-запросы требуют CSRF-токен в заголовке `X-CSRFToken`.

### Формат плана

Ответ на GET и на успешный POST:

```json
{
  "room": {"title": "Спальня", "w": 490, "h": 290},
  "layout": {"id": 1, "title": "Исходный", "created_at": "2026-10-02T06:12:00.123Z"},
  "items": [
    {"id": 1, "kind": "bed", "name": "Кровать", "x": 45, "y": 75, "w": 181, "h": 215, "wall": false}
  ]
}
```

Сохранение варианта (`POST /layouts/<id>/plan/`) принимает только `items`, без `id`. Сервер заменяет всю мебель варианта на присланную:

```json
{"items": [{"kind": "bed", "name": "Кровать", "x": 45, "y": 75, "w": 181, "h": 215, "wall": false}]}
```

Создание варианта (`POST /rooms/<id>/layouts/`) принимает еще название:

```json
{"title": "Кровать у стены", "items": [...]}
```

Ответы с ошибкой, статус 400:

- неверный формат запроса или повторяющееся название варианта: `{"error": "текст"}`;
- предметы не прошли проверку: `{"errors": [{"index": 0, "messages": {"x_coordinate": ["Предмет выходит за правую стену комнаты"]}}]}`, где `index` — номер предмета в присланном списке.

Если при создании варианта хотя бы один предмет не прошел проверку, вариант не создается.
